天池 Research Agent

开放域事实问答 Agent：在单题 55 秒内决定直答、检索还是放弃，并用 SSE 把结果流式返回。

背景与问题

赛题是开放域事实问答，评测按答案精确匹配打分。模型直答快，但容易给出过时或编造的事实；每题都去搜索又会增加延迟并引入噪声，而单题总时限只有约 55 秒。难点不在“能不能调用搜索”，而在于什么时候搜、搜到什么程度、时间不够时怎么体面地退出。

整体流程

  1. 接收问题记录截止时间，之后每一步按剩余时间分配时限
  2. 模型直答候选检查：格式、长度、不确定表达
  3. 检索回退查询改写与拆分，多源搜索并发
  4. 证据整理去重、按词项与实体一致性排序、二跳补搜
  5. 证据作答主模型不通过时升级到更强模型
  6. 归一化与退出按题型整理数字、语言和名字格式，返回答案或 unknown

我做了什么

  • 设计并实现整条问答主流程：直答 → 校验 → 检索 → 证据作答 → 归一化，所有阶段共享一个总截止时间，单步时限由剩余时间计算。
  • 接入 IQS、Tavily、SerpAPI 三个搜索源，统一结果结构后并发调用；单源超时或报错时进入冷却，不影响其他源。
  • 实现查询改写与拆分、基于实体的二跳检索，以及按标题覆盖、词项重叠、年份和实体一致性的可解释排序。
  • 用 AgentScope Runtime 的 AgentApp 部署成服务，/answer 同时支持 JSON 和 SSE：先发 Ping 保持连接，答完发最终消息；客户端断开时取消后台任务。
  • 编写批量回归脚本，固定题集比较各版本的输出覆盖率与耗时，作为每次改动的回归检查。

关键设计与取舍

固定级联为主，ReAct 作为可选分支

做法代码里保留了 LangChain create_agent（底层是 LangGraph 的 ReAct 图）挂载三个搜索工具，但默认关闭。

原因与代价55 秒内需要精确控制每一步的耗时和调用次数；固定流程每步可预测，ReAct 的步数和延迟不可控。代价是少了根据工具反馈灵活改路线的能力。

宁可返回 unknown，也不强行猜

做法最后兜底的“强制作答”和“从文档标题猜答案”默认关闭。

原因与代价评测按精确匹配计分，低置信度的猜测很少得分，还会掩盖真实的失败原因。保留 unknown 可以把失败归到具体环节：工具超时、证据不足还是格式错误。

心跳和结果分开

做法SSE 用独立的 Ping 事件保活，最终答案用另一个事件返回。

原因与代价心跳只说明连接还活着，不代表模型还在产出内容；分开之后，前端和网关都能区分“在等”和“已完成”。

常见追问

这是 RAG 吗？

宽泛地说是检索增强生成，但检索来自运行时调用的外部搜索 API，不是自建的向量库。我控制的是查询构造、多源融合、排序和证据注入，搜索引擎内部的召回不在我的控制范围。

怎么证明检索值得做？

固定题集和模型设置，对照“只直答”“直答 + 检索回退”“再开启 ReAct”三组，记录精确匹配率、unknown 比例、工具调用次数和 p95 延迟，分题型报告。

时间快用完了怎么办？

先给最终校验和回包预留时间；剩余时间不够一次完整调用时不再发起搜索，用已有的有效证据作答，否则返回 unknown。
